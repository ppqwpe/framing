# Framing Web

Mac과 Windows에서 같은 웹 화면으로 사용하는 버전입니다. 기본 작업은 브라우저에서 처리하고, 무거운 작업은 서버에 보냅니다. Windows 앱과 별도입니다.

## 쓰는 순서

파일 선택 → 작업 선택 → 실행 → 결과 다운로드.

파일 선택만으로 서버에 전송하지 않습니다. 서버 작업을 고른 경우에만 비밀번호로 연결하고, 실행 버튼을 눌러 전송합니다.

| 기능 | 기본 처리 위치 |
|---|---|
| 대조 미리보기·대조 PNG | 브라우저 |
| 고르게 / 지정 시간 프레임 뽑기 (PNG·JPG) | 브라우저 |
| 콘택트시트·이름 변경·ZIP | 브라우저 |
| 대조 영상·전체 프레임·EXR·DPX | 서버 |
| 리타임·보간·되돌리기·컷 분할·역재생·검사·변환 | 서버 |

브라우저에서 읽지 못하는 코덱은 처리 위치를 서버로 바꾸세요. 브라우저 추출은 시간 위치 기준이며 정확한 프레임 번호 추출을 보장하지 않습니다. PNG 대조는 A 기준 최대 너비 1920px(나란히는 3840px)로 만듭니다. 브라우저 결과는 페이지를 닫기 전에 내려받으세요. 브라우저 기능도 웹 페이지를 여는 호스팅 주소가 필요합니다.

대조, 프레임 추출, 리타임·보간, 메모로 되돌리기, 컷 분할, 역재생, 샷 검사, 콘택트시트, 변환, 이름 변경을 지원합니다. 대조는 목록의 첫 파일이 A, 두 번째가 B입니다. 이름 변경은 업로드한 복사본에만 적용됩니다.

원본 프레임이 보존된 리타임 결과만 메모로 되돌릴 수 있습니다. 손실 압축 전 원본 화질이나 원본 음성을 복구하는 기능은 아닙니다. 검사는 검토할 후보를 찾는 기능입니다.

## 서버에 올리기

Docker Compose가 있는 Linux 서버와 서버를 가리키는 도메인이 필요합니다. 시작 사양은 CPU 4코어, RAM 8GB, 여유 디스크 40GB입니다. 처리 속도와 동시 이용량에 맞춰 늘려주세요.

1. 이 폴더 전체를 서버에 복사합니다.
2. `.env.example`을 `.env`로 복사하고 도메인과 12자 이상의 새 비밀번호를 입력합니다.
3. 서버에서 `docker compose up -d --build`를 실행합니다.
4. 80·443 포트를 열고 `https://설정한도메인`으로 접속합니다.

사용자는 설치할 필요가 없습니다. 운영자가 한 번 서버를 준비하면 됩니다. Mac에서는 Safari의 ‘Dock에 추가’로 별도 창처럼 사용할 수도 있습니다.

현재 패키지는 소규모 팀용 미리보기입니다. 공용 비밀번호로 접속하며 계정·결제·사용자별 할당량 기능은 없습니다. 무제한 공개 서비스로 배포하기 전 별도 운영 검토가 필요합니다. 기본 컨테이너는 처리 서버의 외부 네트워크 접근을 막습니다.

## RIFE

기본 패키지는 FFmpeg 보간을 제공합니다. RIFE는 별도 Linux용 rife-ncnn-vulkan 실행 파일, 모델, Vulkan 지원 GPU/드라이버와 컨테이너 장치 설정이 필요합니다. 실행 파일을 `FRAMING_RIFE_PROGRAM` 환경변수로 지정하세요. Windows용 exe를 Linux 서버에 넣어서는 실행되지 않습니다. 파일·모델이 있으면 메뉴가 열리지만 실제 GPU 호환성은 해당 서버에서 실행해 확인해야 합니다. 사용자의 Mac에 GPU 도구를 설치할 필요는 없습니다.

## 로컬 개발 미리보기

Python 3.14와 PATH에 있는 FFmpeg/ffprobe가 필요합니다. 가상환경에서 `pip install -r requirements.txt` 후 `FRAMING_ACCESS_PASSWORD`를 설정하고 `uvicorn server:app --host 127.0.0.1 --port 8766`으로 실행합니다. 이 주소는 해당 컴퓨터에서만 열립니다.

테스트: `pip install httpx` 후 `python -m unittest discover -s tests -v`.

## 브라우저 제한

한 번에 20개, 해상도 4K 이하, 프레임 추출 합계 100장, 이미지 결과와 ZIP은 256MB까지입니다. 이름 변경은 내려받는 복사본에 적용되고 원본 파일명은 바뀌지 않습니다. ZIP은 용량 압축 없이 여러 파일을 묶습니다. 브라우저 지원 코덱과 기기 메모리에 따라 큰 파일은 처리하지 못할 수 있습니다.

브라우저 로직 테스트: Node.js에서 `node tests/test_local.mjs`.

## 서버 보관과 제한

파일당 512MB, 작업 공간당 20개·2GB, 영상은 4K·2분·3,600프레임 이하입니다. 작업은 한 번에 하나씩 처리하며 최대 30분·8GB로 제한합니다. 마지막 이용 후 24시간이 지난 공간은 정리됩니다. 서버 재시작 뒤 이전 공간은 복구하지 않으므로 결과를 내려받아 보관하세요. 디스크 여유와 로그는 운영자가 관리해야 합니다.

API는 업로드 ID만 받고 사용자 지정 로컬 경로를 받지 않습니다. 세션별로 파일을 분리하며 비밀번호·요청 토큰·동일 출처 검사를 적용했습니다. HTTPS는 Caddy가 담당합니다. Uvicorn worker 수는 반드시 1로 유지하세요. 상태는 메모리에 있으므로 여러 서버로 확장하려면 공용 작업 큐와 저장소가 추가로 필요합니다.

이 환경에서는 Windows 로컬 서버와 실제 영상으로 검증했습니다. Linux Docker 빌드, 실제 HTTPS 도메인, Mac Safari 및 Linux GPU 실행은 아직 검증하지 않았습니다.
