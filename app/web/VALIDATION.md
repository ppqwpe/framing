# 브라우저 우선 버전 확인 · 2026-10-12

Windows Chromium 미리보기에서 실제 파일 선택 창으로 두 예제 영상을 읽었습니다. 파일 선택 및 기본 처리 중 서버 파일 업로드 요청이 없음을 서버 로그로 확인했습니다.

- 대조 PNG 6종 생성
- 각 영상 2장씩 총 4장 추출
- 콘택트시트 2장 생성
- 대조 동시 재생 시작 및 브라우저 오류 없음 (음성 청취 검증은 아님)
- 새 웹 화면에서 서버 연결 → 두 영상 전송 → B 음성 대조 영상 생성·다운로드 확인: 3840×1080, 185프레임, 오디오 스트림 존재
- 이름 변경 ZIP 다운로드: CRC 검사 통과, 두 영상 SHA-256 원본 일치
- 브라우저 옵션/이름 충돌/취소/CRC 회귀 검사 통과
- 기존 서버 인증·세션 격리·입력 검사 회귀 테스트 통과

Mac Safari, 공개 서버, Linux Docker 및 Linux GPU는 아직 실행 검증하지 않았습니다. 아래는 기존 서버 처리 엔진 확인 기록입니다.

# 확인 기록 · 2026-10-02

Windows 로컬 서버, Python 3.14, FFmpeg, RTX 5070 Ti에서 확인했습니다.

## 실제 소재

- 01_joy_mask.mp4: 1920×1080, 188프레임
- 02_S_result.mp4: 1280×720, 185프레임

## 실행 결과

15개 처리 작업 완료: 이름 변경, 대조 이미지(모든 보기), 대조 영상(B 음성), 프레임 추출, 수동 컷 분할, 역재생, 샷 검사, 콘택트시트, GIF 변환, 복제/FFmpeg 모션/RIFE 리타임 각 1회, 각 리타임 결과 되돌리기 3회.

대조 영상은 3840×1080, 185프레임이며 오디오 스트림이 있습니다. 세 리타임 결과는 각각 220프레임, 되돌린 결과는 각각 원래 길이인 188프레임입니다. 리타임과 복원 결과는 무음입니다. 프레임 수 복원과 무손실 원본 파일 복구는 다릅니다.

브라우저에서 실제 파일 선택 창으로 두 영상 업로드 → 대조 이미지 생성 → 결과 링크 표시 → 새로고침 후 결과 유지까지 확인했습니다. 작업 취소도 실제 처리 중에 확인했습니다.

인증, 잘못된 비밀번호, 요청 토큰, 다른 출처 요청, 파일·결과의 세션 격리, 경로 설정 거부, 파일 삭제, 잘못된 JSON, 위장 영상 거부, 잘못된 옵션 검사를 통과했습니다.

## 아직 확인하지 않은 환경

Linux Docker 이미지 빌드, 실제 도메인과 HTTPS, Mac Safari, Linux용 RIFE 및 GPU 연결. 모든 설정 조합이나 손상된 파일 전체를 검증한 것은 아닙니다. 공개 운영 전 대상 서버에서 위 기능을 한 번 더 확인해야 합니다.
